    11.Why would you use LangChain4j instead of calling the LLM API directly from Java?
    -LangChain4j simplifies LLM integration in Java. Instead of manually creating HTTP requests, JSON payloads, authentication headers, and response parsing, it provides Java-friendly APIs, AI Services, prompt templates, chat memory, tool calling, RAG support, and integrations with multiple LLM providers. This allows developers to focus on business logic rather than low-level API handling.
    12.Suppose your company wants to switch from OpenAI to Google Gemini. How does using LangChain4j make this easier?
    -LangChain4j provides a common Java abstraction over different LLM providers. When switching from OpenAI to Gemini, most of the application code remains unchanged. We mainly update the provider configuration, API key, and model configuration while keeping the business logic and AI Service interfaces the same.
    13.Imagine you're building a customer support chatbot in Java using Spring Boot. Describe the complete request lifecycle from the moment a user sends a message until the AI response is displayed.
    -When a user sends a message to the customer support chatbot, the request goes through the following lifecycle:
    1. The user sends a message through the chatbot interface.
    2. The Spring Boot application receives the message and constructs a prompt for the LLM.
    3. The application uses LangChain4j to send the prompt to the LLM API, including necessary parameters like model name, temperature, and max tokens.
    4. The LLM processes the prompt and generates a response.
    5. The response is sent back to the Spring Boot application in JSON format.
    6. LangChain4j converts the JSON response into Java objects.
    7. The application formats the response and sends it back to the chatbot interface.
    8. The Java application processes the response and returns it to the frontend/user.
